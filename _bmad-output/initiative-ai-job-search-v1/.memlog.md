- (requirement) R1 (Locked: Sources): listings come from Remotive, RemoteOK, We Work Remotely, Himalayas, Jobicy, OnlineJobs.ph, Jobstreet, Kalibrr; each source is verified usable before it is relied on; shown by listings from every verified source appearing in the feed
- (requirement) R2 (Locked: Fetching): listings refresh in the background on a schedule, default every 30 min, without user action; opening the app shows stored listings without waiting on any source
- (requirement) R3 (Locked: Eligibility first): every listing is tagged worldwide, APAC, PH-friendly, restricted, or unknown; the feed shows the first three, unknown with a warning badge, and never restricted
- (requirement) R4 (Locked: Ranking): the feed groups listings into freshness tiers (<24h, 1-3d, older) and orders each tier by match score against the user's CV skills
- (requirement) R5 (Locked: Ranking): listings below a user-set minimum match score, default 40%, are hidden
- (requirement) R6 (Locked: Ranking): when a listing's posted date is missing or unreliable, freshness uses the time the fetcher first saw it
- (requirement) R7 (forge core flow): the user sets a role/skillset preference (e.g. Frontend, ReactJS) and the feed shows only listings matching it
- (requirement) R8 (forge core flow): the user opens a listing to read its full job description and follow a link to the original posting to apply
- (requirement) R9 (Locked: Resume): the user uploads a PDF CV once and gets a structured master resume (summary, skills, experience, projects) parsed by Claude
- (requirement) R10 (Locked: Resume): the user reviews and corrects the master resume before it is used for matching or tailoring
- (requirement) R11 (Locked: Resume): for a chosen listing the user gets a resume tailored to its job description, built only from the master resume
- (requirement) R12 (Locked: Resume): the tailored resume downloads as a PDF in the app's own ATS-friendly template
- (requirement) R13 (derived from Ranking + Resume): match scores use the skills in the reviewed master resume
- (constraint) C1 (forge idea: zero budget): no paid services; data stored in local MongoDB; runs on the user's machine
- (constraint) C2 (Locked: Claude): Claude is called only through Claude Code headless (claude -p) on the user's subscription, no API key, and only for resume parsing and tailoring
- (constraint) C3 (Locked: Claude): fetching, eligibility tagging and ranking use no LLM (rules and a skill dictionary with synonyms)
- (constraint) C4 (Locked: Guardrail): tailoring reorders and rewords facts from the master resume only; it never invents skills or experience
- (constraint) C5 (Locked: Sources): prefer public APIs/RSS over HTML scraping; LinkedIn/Indeed are not sources (crowded feed, fragile, ToS risk)
- (constraint) C6 (Risks: subscription limits): Claude runs only on explicit user action, never in bulk over the feed
- (constraint) C7 (Risks: build vs apply time): v1 is time-boxed to about two weeks from 2026-11-27; scope that threatens the box is cut, not extended
